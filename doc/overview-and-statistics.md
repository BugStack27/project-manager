# 总览与统计 — 决策记录

> 状态：✅ 已验收（2026-10-28）

## 1. 目标与范围

- **总览**：启动后默认落在一页，一屏看清全部项目的三类状态（待处理需求 / 未提交改动 / 运行中服务），能就地启停服务；看细节时点对应列落到三页的对应上下文。
- **统计**：左栏全局页，回答「最近干了多少活」——提交次数 / 新增行数 / 删除行数（代码活动）与已处理 / 已完成 / 已拒绝（需求处理）六项指标、每日趋势图、按项目明细表。

**做**：跨项目汇总、行内启停、点列深链、空闲项目折叠；三档时间范围（7 天 / 30 天 / 本月）、全部 / 单项目筛选、明细排序、手动刷新与缓存。
**不做**：总览的筛选器、行内展开清单、首页改需求状态、图表 / 趋势、日志与 diff 预览；统计的自定义区间、`closedAt` 数据模型变更、归档项目、定时刷新、图表库、MCP 工具。

## 2. 关键决策

### 2.1 总览

| 决策点 | 结论 | 理由 |
|---|---|---|
| 入口与首屏 | 导航顶部新增「总览」，作为启动默认页 | 汇总页不首屏出现，等于多一次点击才叫「首页」 |
| 筛选器 | 删除（不设 seg，计数条不可点） | 为比较三类状态反复切筛选，正是「需要切换太多」的根源 |
| 列内容（2026-11-12 简化） | 每列只占一行，只给最该看的关键信息：需求列 = 最该看的一档状态胶囊 + 未完成总数（无待办时给候选条数）；改动列 = 文件数 / 干净 / 非 git 仓库 + 远程 ↓N；运行列 = 运行中 x/y + 命令名（未运行时 0/y）。文件名、运行时长、上次结果、完整需求分布全部收进单元格 tooltip | 三列各两行会把行高撑到近两倍，但副行的内容点一下列就能看到；扫视时一行足够回答「这个项目要不要处理」 |
| 就地操作 | 仅启停命令（单命令直连、多命令下拉） | 需求流转要备注弹窗与终态备注替换，搬进首页等于半个需求编辑器 |
| 点列去向 | 需求列 → 需求中心（选中该需求）；改动列 → 修改记录；运行列 → 启动台（自动开运行中日志） | 各列直达目标页，比统一跳需求中心少一次切换 |
| 空闲项目 | 折叠到列表末尾，不靠筛选降噪 | 折叠是一次性展开，筛选是反复切换 |
| 数据接入 | 后端只加字段、不加接口：`projectView.commands`、`git.statusCount.sample` | 在已解析数据上取，零额外子进程 |
| 右面板 | 每次切换到总览都收起；总览不提供展开入口（状态栏无面板开关） | 总览没有详情可看，展开只会是一片空壳盖在内容上 |
| 状态栏标题 | `PageBar` 增 `icon` 插槽，各页统一用与左栏导航同套图标 | 同一「你在哪」的概念不该有两套图形语言 |

### 2.2 统计

| 决策点 | 结论 | 理由 |
|---|---|---|
| 入口 | 左栏「总览」下的全局导航项 | 统计口径天然跨项目，放进项目内视图页签会要求先选项目 |
| 需求完成时间 | 用 `updatedAt` 近似，不加 `closedAt` | 零迁移；代价是完成后改备注会把需求算进改动那周，页面口径如实说明 |
| 取数窗口 | 一次取回 `min(月初, 今天-29)..今天`，切换范围纯前端切片 | 三档切换零请求 |
| 归档项目 | 排除 | 与 git 汇总、侧栏口径一致 |
| 刷新 | 进页仅无缓存时加载 + 手动刷新按钮；项目集合变化后缓存失效 | 符合「刷新不遮内容」惯例 |
| 代码口径 | 当前分支、非合并提交、项目目录范围、二进制不计行 | 与修改记录页既有口径一致 |
| 图表 | 原生 SVG 手绘，交互用透明 rect 承载 | 不引库；SVG `<g>` 无法聚焦，透明 rect 才能接键盘 / 点击 |
| 失败降级 | 单项目 git 失败只降级该项目；并发 4、单项目 30s 超时、`truncated` 标记 | 一个坏仓库不能拖垮整页 |
| 日期校验 | 拒绝非法日期与超过 62 天的跨度 | 防 `2024-02-30` 进位与超大查询 |

## 4. 关键修正与教训

- **表头与内容整体错位** → 末列表头是空 `<span>`、数据行是按钮组，两套 grid 解析出不同列宽；末列必须固定宽度，行内按钮右对齐。
- **一屏浅灰字太多、费眼** → 次级信息统一 `--label-2` + 12px，只有项目路径保留 `--label-3`。
- **项目列与需求列看起来重叠** → 多不是 overflow，而是文案过长加间距过小；先裁文案再加大间距比加宽列有效。
- **「读不到」不能显示成「没改动」** → `gitSummary` 未就绪时改动列显示 `—`；空闲判定要求 git 明确返回且干净。
- **深链会被切项目的重置 effect 清掉** → 目标 id 先存 `pendingNav`，等项目确属该 `reqsPid` 后再落地。
- **同一动作三处三种样子** → 启停统一 `.btn.start` / `.btn.stop`；看日志的选中行与需求行选中保持同一套视觉。
- **备注名不显示** → 命令的 `name` 早已存在，启动台行首、日志面板顶部、总览运行列三处补显示，命令原文进 `title`。
- **非法日期会静默进位** → 必须显式校验年月日，而不是只判断能否解析。
- **超大仓库的 `--numstat` 会撑爆 stdout** → 并发 4 + 单项目 30s 超时 + `truncated` 标记，失败项目留空但不拖垮整页。
- **统计页的项目切换必须与总览同构** → 侧栏点项目在总览 / 统计页都进入需求中心，不产生第三种状态。
- **缓存失效要跟随项目集合变化** → 新建 / 改路径 / 归档 / 恢复 / 删除后清统计缓存，否则数字停在旧集合。
- **图表可点不等于可聚焦** → SVG `<g>` 无法键盘聚焦，交互热区用透明 `rect` 承载。

## 5. 已知边界

- 总览三列都只显示一行：改动列给文件数（远程给 ↓N），文件名清单在 tooltip；运行列给正在跑的第一条命令与 x/y，时长与「另 N 条」在 tooltip；需求列只给最该看的一档状态与未完成总数，候选条数与完整分布见 tooltip，都不给候选标题（点进需求中心看）。
- 总览排序按关注度加权，状态变化会小幅重排；未做虚拟滚动，按「未归档项目 ≤ 50」设计；首页启停与启动台共享 runner，重复启动返回 409。
- 统计用 `updatedAt` 近似：完成后改备注会重新计入改动那周，同一需求只在最后更新时间所在周出现一次。
- 统计大仓库 31 天 `--numstat` 可能超 8MB stdout 缓冲，靠并发、超时与截断兜底；多项目指向同一仓库或父子目录会各算一次。
- 统计按本地自然日，跨时区不在范围；只有已加载范围内的数据，超出 62 天的区间不开放。

## 6. 后续候选

- 需求状态流转进首页（需解决备注弹窗与终态备注替换的呈现）；首页右面板做日志 / diff 预览。
- 统计的自定义区间与周 / 月对比；基于事件日志计算 lead time / cycle time，替代 `updatedAt` 近似。
