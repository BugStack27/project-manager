# 个人项目管理台 · 功能方案

> 适用对象：本人。目标：统筹管理本地代码项目，管“该做什么 + 怎么跑起来”，并支持外部 AI 提需求、认领与交付。

## 一、形态

- Electron 桌面应用（本地单进程）：界面走 IPC（`window.pm.invoke`），AI 助手走应用内本地 HTTP MCP（127.0.0.1:7318）。
- 面板与外部 AI 共同依赖同一套领域方法（IPC 方法 / MCP 工具 / `/claim`、`/complete` 兜底接口），保持单一写入者。
- 关闭窗口驻留托盘；退出时若有活跃命令（含已分离仍存活的进程），先问「分离 / 停止 / 取消」。

## 二、顶层结构

- **总览**：默认首页，三类状态同屏（需求 / 启动 / 改动），点行直达对应页面；不选具体项目。
- **统计**：跨项目汇总提交次数、增删行数与需求处理量，支持 7 天 / 30 天 / 本月与单项目筛选。
- **需求中心** —— 管“这个项目该做什么”
- **启动台** —— 管“这个项目怎么跑起来”
- **修改记录** —— 读取项目本地 git 仓库：提交历史、未提交改动、远程同步（拉取 / 推送）与本地提交

项目内三块视图并列，都作用于当前选中项目；三者通过中区顶部的紧凑页签切换（`Ctrl / ⌘ + Tab` 循环），引用同一份“项目注册表”（名称 / 路径），但数据与页面各自独立。左栏提供拖拽排序、已归档分组与底部「设置与数据」浮层（备份、通知、MCP、键盘快捷键、审计、检查更新）；`Ctrl / ⌘ + K` 可跨项目搜索项目 / 需求 / 日志 / 提交。

## 三、需求中心

### 核心概念

- 每个项目独立一组需求；需求是项目下的子资源，与启动命令完全分开。
- **不限条数**：一个项目可以同时存在任意多条未完成需求，新建接口不校验条数。
  - 未完成 = 状态为 `未开始` / `进行中` / `待审核`。这个口径仍用于侧栏计数、视图页签与筛选，只是不再作为拦截条件。

### 状态机（5 态）

| 状态 | 含义 |
|---|---|
| 未开始 | 新提的，待处理 |
| 进行中 | 已认领 / 已决定做 |
| 待审核 | agent 已交付，等验收 |
| 已完成 | 验收通过 |
| 已拒绝 | 不需要该需求（终态） |

### 协作元数据

- `claim = { agent, at }`：执行 agent 认领后写入；认领把未开始置为进行中，撤销回未开始即释放。视图另带 `agentName` 供界面展示，`agent` 始终是 AgentID。
- `completion = { agent, at, note }`：agent 交付时写入；通过后保留作历史，打回只清交付信息、保留认领。视图同样带 `agentName`。
- `feedback = { at, note, kind }`：打回（`kind = rejection`）与撤销已完成（`kind = reopen`）时必填原因，随需求视图出现在 `/claim` 与详情里，agent 再次认领可读到。
- 进行中支持撤销：有认领时二次确认，退回未开始并释放认领；已完成撤销先弹窗填原因，同时追加一条「撤销」往返记录。

### 能力

- 按项目查全部需求、查未完成需求。
- 新建需求（不限条数）、编辑、改状态（含转已拒绝、标记已完成、打回、撤销）。
- 面板支持手动新建需求，也支持查看外部 AI 新增需求，逐条决定开始 / 完成 / 拒绝。
- 需求详情展示最近事件时间线；已有往返记录时时间线收成「事件记录 · 查看全部」入口，不重复列表；「查看全部」进入审计日志并按该需求筛选。
- 「复制内容」给出标题 + 正文 + 备注；「复制给 Agent」只给认领指引，agent 认领后从接口取完整内容。
- 标记已完成 / 已拒绝时弹窗填写备注：终态下原备注通常已过时，用这条备注整条替换；留空即清空。提交并自动审核同样清空备注。撤销已完成弹窗必填原因，写进往返记录并回传给下次认领的 agent。

### 记录字段（精简）

标题、正文、来源（AI / 手动）、创建时间、状态、备注、认领、交付、反馈。

## 四、启动台

- 每项目挂一组**一键启动命令**（如 `npm run dev`、`docker compose up`…），点一下即启动，显示运行状态（运行中 / 已分离 / 已停止）。
- **保留完整进程日志**，可查看某次启动的历史输出；日志渲染 ANSI 颜色，支持搜索按可见文本定位。
- 命令由独立中转宿主进程托管：应用退出可选分离，进程与日志继续运行；下次启动显示「已分离 · 仍在运行 / 已退出」，并可在应用内停止。
- 命令登记工作目录；项目改路径后，本项目命令的工作目录随之同步，运行中的进程不迁移。
- 仅负责“怎么跑”，不掺需求逻辑。

### 记录字段

项目、命令文本、工作目录、启动时间、运行状态、日志、宿主进程。

## 五、IPC 方法 / MCP 工具（契约层，面板与外部工具共用）

- **项目**：列全部 / 取单个 / 新建 / 编辑 / 归档 / 恢复 / 删除归档项目 / 拖拽排序。
- **需求**：按项目查全部 / 查未完成 / 新建（带门槛）/ 更新状态 / 编辑 / 删除；`GET /claim` 认领、`GET /next` 取即认领（没活时长等）、`POST /complete` 交付、`POST /ask` 提问、`POST /release` 释放。
- **启动**：列命令 / 执行启动 / 停止 / 查运行状态 / 查日志。
- **修改记录**：汇总 / 提交列表 / 当前改动 / diff / 单提交文件 / 远程位置 / 拉取 `--ff-only` / 推送当前分支 / 本地提交。
- **统计**：按日聚合代码提交与增删行、需求处理量。
- **搜索**：`globalSearch` 一次返回项目 / 需求 / 日志 / 提交四组结果，支持深链跳转。
- **事件与设置**：事件查询 / 需求时间线 / 通知设置读写。
- **系统**：IDE 与终端打开项目、数据备份与恢复、MCP 端点信息、外链打开。
- **桌面运维**：检查 / 下载 / 安装更新、崩溃记录与诊断包导出（进程级能力，不进领域 dispatch）。

> 契约先固定结构，前端与外部工具都依赖它，优先级最高。MCP 工具表以 `electron/mcp-http.js` 为准。

## 六、夜间巡检（运行约定，不进需求文档）

- 外部 cron 在低峰启动一次 AI 会话，通过 skill 调 MCP 工具：
  `列项目 → 按 aiScout 筛候选 → 读代码 / git / 文档 → 提需求`。
- 执行侧：agent 先 `/claim` 认领、完成后 `/complete` 交付并在服务端等验收（最长 30 分钟），用户点通过即完成、写回复则带回意见让 agent 继续开发并再次交付，由用户最终验收。
- 系统只提供判据与门槛，不内置调度器。

## 七、通知与审计

- 系统通知三类：待审核交付、命令异常退出/启动失败、AI 新增需求；总开关 + 分项开关；AI 60 秒合并、命令 5 分钟冷却；正常退出/手动停止/启动恢复不通知。
- 托盘待审核角标：只统计非归档项目的 review 需求，1–9 / 9+；菜单可按项目直达。
- 事件日志按项目 append-only JSONL，永久保留；需求详情时间线 + 全局只读审计（项目/类型/操作者/时间筛选，已删除实体只展示快照）。
- 不做收件箱/未读；错过通知从时间线与审计回溯。
- 事件文件与 db.json 解耦：恢复备份不改事件；每日快照不含事件。

## 八、桌面运维

- **自动更新**：安装版启动 8 秒后首检、之后每 6 小时检查；不做静默下载，下载与重启安装都由用户点；开发版与未配置更新源的版本只给说明。
- **发布流水线**：推 `v*` 标签触发 GitHub Actions，校验 tag 与 `package.json` 版本一致后构建 Windows 安装包，并把 exe / blockmap / `latest.yml` 发到 Release。
- **崩溃诊断**：主进程异常、渲染崩溃、子进程崩溃与渲染端 ErrorBoundary 异常写入 `<数据目录>/crash`；版本弹窗可导出诊断包，不包含项目正文。
- **恢复守卫**：有活跃命令（含已分离且宿主存活）时拒绝覆盖 `db.json`，避免旧库写回。

## 九、技术栈与架构

- 技术栈：Electron + React / Vite。
- 前端走 IPC（`window.pm.invoke`），AI 助手走应用内本地 HTTP MCP（见 [architecture-and-channels.md](architecture-and-channels.md)）；v1 的 REST API 已移除。
