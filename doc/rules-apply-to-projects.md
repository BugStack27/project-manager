# 规则一键应用到其他项目 — 任务规划

> 状态：✅ 已实现（2026-11-25），等待验收

## 需求概述

项目设置弹窗的「规则」分区目前只能在当前项目内增删改。很多规则（如收敛文档、代码风格）对多个项目通用，逐个项目重录成本高。

目标：在规则分区提供「应用到其他项目」入口，勾选要复制的规则与目标项目后一次写入。复制保留标题、正文与启用状态；目标项目已有标题与正文都相同的规则时跳过，不覆盖也不产生重复条目；目标项目规则数受既有上限 30 条约束。不改动源项目，不动关联、环境等其他分区。

## 设计决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 作用单位 | 一次应用多条规则到多个项目 | 需求是「一键应用到其他项目」，规则集通常整组通用；逐条复制要反复开关面板 |
| 目标写入方式 | 追加，不覆盖 | 目标项目可能已有自己的规则；覆盖会静默丢配置 |
| 重复判定 | 标题与正文都相同才跳过 | 同名不同内容的规则可能是目标项目的本地版本，保留 |
| 上限与越界 | 沿用 `EXTRA_CAPS.rules = 30`，写满即停并回报跳过数 | 与现有保存校验同一口径，不在批量入口另立规则 |
| 执行位置 | 新增领域动作 `applyRules`，一次落库 | 前端逐个项目保存会在中途失败时留下半套结果，且重复判定要读每个目标的最新规则 |
| 入口形态 | 规则分区内的内联面板（与「批量粘贴」同构） | 设置弹窗本身已是一个 modal，再叠一层要处理 Esc 与层级，内联面板更稳 |
| 默认勾选 | 默认勾选启用中的规则，目标项目默认为空 | 停用规则通常不该扩散；目标项目由用户明确选择，避免误写 |

## Requirements

### 1. 后端批量应用动作

| 属性 | 值 |
|------|-----|
| **目标** | 新增 `applyRules({ sourceProjectId, ruleIds, targetProjectIds })`：校验源项目、目标项目存在且未归档、排除源自身与重复目标；`ruleIds` 缺省表示源项目全部规则；向每个目标追加尚未存在的规则（新分配 `pr` id），写满 30 条停止；有实际写入时更新目标 `updatedAt`、写 `project.updated` 审计（`changes: ['rules']`、`appliedFrom` 源项目名）并 `store.save()`；返回 `{ source, results[], added, skipped }`。`api.js` 暴露同名方法。 |
| **涉及文件** | `electron/services/domain/projects.js`、`web/src/api.js` |
| **验收标准** | 复制成功后目标 `extras.rules` 出现对应条目且启用态一致；标题与正文相同的规则不重复追加；目标已有 30 条时不再新增并在结果中体现跳过；自选源项目、空规则、空目标、已归档目标分别返回 4xx；`npm run check` 通过。 |
| **依赖** | 无 |

### 2. 规则分区批量应用面板

| 属性 | 值 |
|------|-----|
| **目标** | `RulesSection` 顶部信息行增加「应用到其他项目」开关；展开后显示规则勾选列表（默认勾选启用项，停用项标注）、目标项目搜索与多选列表（排除当前项目和已归档项目）、底部「取消 / 应用」与「n 条规则 → m 个项目」摘要。应用成功后 Toast 回报新增与跳过数量并收起面板，失败保留面板与勾选。新增面板样式，复用 `pset-info`、`pset-picker` 的视觉语言。 |
| **涉及文件** | `web/src/components/ProjectSettingsModal.jsx`、`web/src/styles/modal.css` |
| **验收标准** | 规则分区出现入口且无规则时不可展开；默认只勾选启用规则；目标项目可搜索（中文/拼音）、多选、全选与清空；未选规则或未选项目时「应用」禁用；成功后源项目规则不变、目标项目出现副本；重复应用同一批规则提示全部跳过；`npm --prefix web run build` 通过。 |
| **依赖** | 1 |
