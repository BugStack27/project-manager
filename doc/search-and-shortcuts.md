# 搜索与快捷键 — 决策记录

> 状态：✅ 已验收（2026-11-03）｜拼音搜索补充（2026-11-10）

## 1. 目标与范围

- **全局搜索**：`Ctrl / ⌘ + K` 命令面板，在一个输入框里同时搜索项目、需求、运行日志与 git 提交，分组展示、键盘导航，回车直达对应详情，减少「先切项目再翻页面」。
- **项目切换**：`Ctrl / ⌘ + O` 命令面板，按项目名或拼音模糊匹配，回车直接切到该项目；空查询按侧栏顺序列出全部项目，方向键即可直达。
- **快捷键**：把散落在各组件里的全局快捷键收成一份可查看、可改键的清单，弹窗内录制新组合、即时生效并持久化，支持单项 / 全部恢复默认。

**做**：四类结果一次返回、分组与深链跳转、扫描预算与缓存；项目切换面板的中文模糊匹配与高亮；统一动作清单与分发、录制式改键、冲突校验、恢复默认、输入场景让路。
**不做**：搜索审计事件 / 命令名称 / 归档项目、快捷动作、历史查询、正则 / 大小写敏感 / 按字段限定、结果分页；页面内局部操作（启停、需求流转）的快捷键、清除绑定、后端接口、跨设备同步。

## 2. 关键决策

### 2.1 全局搜索

| 决策点 | 结论 | 理由 |
|---|---|---|
| 接口形态 | `globalSearch({ q, limit })` 一次返回四组结果；`q` 去首尾空格并截到 100 字符 | 面板一次请求即可渲染，不串四个接口 |
| 结果形状 | `{ q, projects, requirements, commits, logs, more, partial }`；除项目组外每条自带 `projectId / projectName`；`limit` 默认 5、最大 10 | 跳转不依赖前端再查项目；单组过多只标 `more` |
| 项目匹配 | 名称；从头命中优先，其余按名称排序；支持拼音（`xiangmu` / `xmgl` 都能命中「项目管理」） | 名字类内容用户常常只记得读音 |
| 需求匹配 | 标题 / 正文 / 备注 / `#编号`，按 `updatedAt` 倒序 | 需求是最常找的内容 |
| 日志匹配 | 剥离 ANSI 后按可见文本匹配，返回运行 id、行号与命中片段 | 日志按 ANSI 渲染，搜索必须按用户看到的文字 |
| 提交范围 | 每项目最近 30 条（与修改记录首屏一致），匹配标题 / 作者 / shortSha；按项目串行查询，缓存 60s | 并发起 N 个 git 进程会卡界面；30 条保证跳转后能当场展开 |
| 日志范围 | 全部未归档项目的命令，每命令最近 3 次运行、单命令最多 2 条；已结束运行的可见文本缓存，上限 60 份 | 512KB/次的日志重复读取代价高；实时运行不缓存 |
| 扫描预算 | 提交与日志共用单轮 1500ms 预算，超出即停并返回 `partial` | 宁可少几条，也不让输入卡顿 |
| 分组展开 | 默认每组 5 条；组标题右侧的「＋」改成「查看更多」，点击按 `limit=10` 重查并只展开该组，其余组仍截回 5 条；换关键字后展开状态清零 | 被截断的那条能直接点开、回车直达，又不必给全局翻页加扫描成本 |
| 深链跳转 | 复用 `pendingNav`：需求带 `reqId`，日志带 `logCmdId + runId + logFind`，提交带 `commitSha` | 与总览 / 审计深链同一套机制 |
| 提交展开 | 目标项目 git 列表加载完成后按 sha 调 `toggleCommit`，找不到则提示 | 不在已加载列表里无法展开，明确告知而非静默失败 |
| 日志定位 | 传入命中行号，按「目标行之前的命中数」设置搜索序号 | 只给关键字会停在第一次命中，未必是目标行 |
| 响应竞态 | 250ms 防抖；每次请求带序号，过期响应直接丢弃 | 后发请求可能先回，旧结果不能覆盖新结果 |
| 视觉 | 亮色卡片、蓝色选中底、命中文字高亮，复用 tokens 与 `--sh-sheet` | 与现有弹窗体系一致 |

### 2.2 项目切换面板

| 决策点 | 结论 | 理由 |
|---|---|---|
| 匹配范围 | 项目名称；同时支持文字命中与拼音首字母；空查询按侧栏拖拽顺序列出全部未归档项目 | 与全局搜索同一口径；空查询就是「全部项目的快捷入口」 |
| 模糊规则 | 连续命中（子串）优先于子序列命中；词首命中与靠前命中加分，连续段越多、间隔越小得分越高 | 输入「项管」也能命中「项目管理器」，同时避免弱匹配压过精确命中 |
| 拼音匹配 | 一套口径覆盖全部搜索入口：连续命中 > 子序列命中 > 拼音命中三档打分；拼音档同时接受全拼（`xiangmu`）、首字母（`xmgl`）与汉字拼音混输（`项mu`）；字表用 `pinyin-pro`，多音字取该库默认读音 | 五处搜索框（全局搜索、Ctrl+O、@ 引用项目、/ 引用技能、Ctrl+P）如果各写一套，同一次输入在不同框里命中不同东西；三档保证文字命中永远压过拼音命中 |
| 中文 | 文字匹配按字符原样比较，大小写对拉丁字母不敏感 | 项目名多为中文，字符子序列已能覆盖大部分输入 |
| 多词查询 | 按空白拆词，每个词都要在名称里命中 | 与「筛选是 AND」的直觉一致 |
| 交互 | 上下键循环选择、回车切换、Esc 关闭；默认停在当前项目；输入框内可再次按 Ctrl/⌘+O 收起 | 与另外两个命令面板保持一致 |
| 切换落点 | 总览 / 统计没有当前项目语义，落地到该项目的需求中心；其余页面只换项目、不换页 | 与侧栏点击项目的既有口径一致 |
| 高亮 | 按命中下标合并连续段渲染 `mark`；拼音缩写命中时高亮对应的原字符 | 中文单字命中时逐字描边会断开，合并后读起来是整段 |
| 互斥 | 与全局搜索、启动命令面板互斥，打开一个自动收起另外两个 | 同一时刻只留一层浮层 |

### 2.3 快捷键机制

| 决策点 | 结论 | 理由 |
|---|---|---|
| 数据层 | `lib/shortcuts.js`：动作清单、`{mod, alt, shift, key}` 绑定、加载 / 保存、匹配、冲突、格式化 | 快捷键只有一个真源，弹窗与分发读同一份 |
| 分发 | `useShortcuts` 单一 `window` keydown 按绑定调用 handlers；弹窗、输入控件、输入法组合态让路 | 避免多处监听互相抢键，改键立即生效 |
| 默认动作 | 返回上一页 `Alt+←`、切换视图页签 `Ctrl/⌘+Tab`、全局搜索 `Ctrl/⌘+K`、切换项目 `Ctrl/⌘+O`、命令面板 `Ctrl/⌘+P`、新建需求 / 命令 `Ctrl/⌘+N`、快捷键设置 `Ctrl/⌘+/` | 沿用既有习惯，清单集中维护 |
| 按视图分流 | `create` 一条动作在两种视图里指两件事：需求中心弹新建需求、启动台弹新增命令；其它视图只给一句提示 | 同一组合不能登记成两条动作（冲突校验会让其中一条永远失效），分流只能发生在 handler 里 |
| 设置入口 | 左栏「设置与数据 → 界面 → 键盘快捷键」，`Ctrl/⌘+/` 亦可直接打开 | 可发现与快捷两条路 |
| 录制规则 | 必须含 `Ctrl/⌘` 或 `Alt`；仅按修饰键只做预览；`Esc` 只取消录制 | 避免纯字母 / 纯 Shift 误触，录制中不关弹窗 |
| 冲突处理 | 拒绝保存并提示占用方，保留原绑定；恢复默认同样校验 | 不允许两个动作抢同一组合 |
| 持久化 | `localStorage` key `pm.ui.shortcuts`；缺项回落默认；写入失败静默忽略 | 与布局记忆同一套写法 |
| 脏数据 | 任一重复组合 → 整份回退默认 | 分发只执行第一个，重复会让后一项永久失效 |
| 输入框例外 | 仅放行面板自己输入框（`.cmdk-input`）内的开关组合 | 否则面板打开后无法用原组合收起 |
| 弹窗层级 | 快捷键弹窗打开时收起侧栏「设置与数据」浮层 | 否则浮层压在弹窗上 |

## 4. 关键修正与教训

- **搜索窗口与跳转范围不一致会造成「搜得到但点不过去」** → 提交搜索窗口从 50 收到 30，与修改记录首屏已加载范围对齐。
- **日志直接搜原始文本会与用户看到的文字对不上** → 必须剥离 ANSI 后再匹配，并返回行号。
- **只给关键字会停在第一个命中** → 日志定位需按目标行之前的命中数设置搜索序号。
- **并发起 N 个 git 进程会卡界面，实时运行日志缓存会展示旧内容** → 提交串行查询并缓存，日志只扫最近 3 次运行，只有已结束运行进缓存。
- **连续输入会出现响应乱序** → 每次请求带序号，只接受最新一次响应。
- **全局快捷键不能无条件生效** → 弹窗打开、输入法组合态、输入控件聚焦时必须让路，命令面板自身输入框例外。
- **脏数据只回退冲突项仍会重复** → 任一重复组合必须整份回退默认，否则后一个动作永久失效。
- **只按修饰键曾被当成完整组合** → 录制时用空主键做预览，等主键按下才保存。
- **`Ctrl/⌘+/` 打开时侧栏浮层压住弹窗** → 弹窗打开即收起浮层。
- **组标题的「＋」只提示还有更多却点不开** → 「＋」换成「查看更多」，点击按上限 10 条重查并只展开该组；展开后仍超出时保留「＋」做提示，不再重复给入口。
- **拼音命中一旦与文字命中同分就会盖掉精确结果** → 拼音档基数必须整体落在子序列档之下（240 < 260 起）；反过来，跨度过大的子序列命中被截到 1 分，这时让位给干净的拼音命中是合理的。
- **首字母与全拼拆成两条路会漏掉混输** → 「先取首字母串再分别匹配」无法处理 `项mu`；按「查询逐字消费原文的音节」一条对齐规则同时覆盖全拼、首字母与混输。
- **几百条需求逐字转拼音会拖慢每次按键** → 主进程按「原文无汉字」「查询无拉丁字符」两个条件提前退出，这类调用连词表都不碰。
- **首字母用系统中文排序器推断（旧实现）在非拼音排序的系统上是错的** → 排序器不可用时整档静默失效，且拿不到全拼；换成显式字表后规则稳定、可测。

## 5. 已知边界

- 不搜索审计事件、命令名称、归档项目及其需求 / 日志 / 提交；提交只覆盖最近 30 条，日志只覆盖每命令最近 3 次运行且只到文件尾 512KB。
- 结果每组默认 5 条、点「查看更多」后最多 10 条（接口上限），仍超出只标 `more`，无分页与历史查询；不支持正则、大小写敏感、按字段限定。
- 快捷键组合必须含 `Ctrl/⌘` 或 `Alt`；不支持清除绑定与跨设备同步；动作清单目前 7 条，新增需同时接入 handlers 与默认绑定。
- 项目切换只覆盖未归档项目的名称，不搜路径与项目内需求。
- 拼音匹配的范围：项目名、技能 id / 名字 / 描述、命令名 / 命令文本 / 所属项目名、需求标题与备注、提交标题与作者。**需求正文与运行日志不做拼音** —— 正文转拼音的代价随字数线性增长、长文散命中噪音大，日志是程序输出没有读音；两者仍按子串匹配。
- 多音字取字表默认读音，不做上下文消歧（「重庆」按 `chong`）；拼音档是贪心顺序对齐，不做回溯最优对齐。
- 全局搜索的**文字**匹配仍是子串，只有候选类搜索（Ctrl+O、@、/、Ctrl+P）做子序列模糊 —— 正文与日志放宽到子序列会把几乎每条都算命中。
- 面板交互与四类深链依赖桌面端实际运行验收。

## 6. 后续候选
